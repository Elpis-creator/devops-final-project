\# DevOps Deployment Dashboard



\*\*Підсумковий проєкт з DevOps\*\*



\## 1. Опис проєкту



DevOps Deployment Dashboard — вебзастосунок, розроблений для демонстрації автоматизованого процесу тестування, контейнеризації та розгортання програмного забезпечення у хмарній інфраструктурі AWS.



Застосунок відображає поточний стан сервера, підключення до бази даних PostgreSQL та версію розгорнутого програмного забезпечення.



Основна мета проєкту — реалізувати повноцінний CI/CD-процес від внесення змін у GitHub до автоматичного оновлення застосунку на AWS EC2.



\## 2. Використані технології



| Технологія | Призначення |

|---|---|

| Node.js | Серверне середовище виконання |

| Express.js | Створення вебзастосунку та REST API |

| PostgreSQL 15 | Реляційна база даних |

| Jest | Автоматизоване тестування |

| Docker | Контейнеризація застосунку |

| Docker Compose | Керування контейнерами |

| Docker Hub | Зберігання Docker-образів |

| GitHub Actions | Автоматизація CI/CD |

| Terraform | Створення хмарної інфраструктури |

| HCP Terraform | Зберігання стану Terraform |

| AWS EC2 | Хмарний сервер для розгортання |

| Ubuntu 24.04 | Операційна система сервера |



\## 3. Архітектура системи



Проєкт складається з двох основних контейнерів:



\- \*\*app\*\* — вебзастосунок Node.js, який обробляє HTTP-запити, відображає Dashboard та взаємодіє з PostgreSQL.

\- \*\*db\*\* — база даних PostgreSQL 15, яка працює в окремому Docker-контейнері.



Взаємодія компонентів:



```text

Користувач

&#x20;   |

&#x20;   v

Веббраузер

&#x20;   |

&#x20;   v

AWS EC2 (Ubuntu 24.04)

&#x20;   |

&#x20;   v

Docker Compose

&#x20;   |

&#x20;   +-- Node.js + Express

&#x20;   |       |

&#x20;   |       v

&#x20;   |   PostgreSQL

&#x20;   |

&#x20;   +-- Docker Volume

```



Застосунок доступний через HTTP-порт 3000. Доступ до нього обмежується правилами AWS Security Group.



База даних PostgreSQL не публікує свій порт у зовнішню мережу.

\## 5. Локальний запуск



Для запуску проєкту необхідно встановити Docker та Docker Compose.



Перейти до каталогу:



```bash

cd students/sivanna

```



Створити файл `.env` із параметрами:



```env

POSTGRES\_USER=postgres

POSTGRES\_PASSWORD=your\_secure\_password

POSTGRES\_DB=devops\_dashboard

```



Запустити контейнери:



```bash

docker compose up -d --build

```



Перевірити їхній стан:



```bash

docker compose ps

```



За стандартними налаштуваннями локального Compose застосунок доступний за адресою:



```text

http://127.0.0.1:3001

```



Для зупинки:



```bash

docker compose down

```



\## 6. Автоматизоване тестування



Для тестування використовується Jest.



Встановлення залежностей:



```bash

npm ci

```



Запуск тестів:



```bash

npm test

```



Тести перевіряють роботу вебзастосунку та його API.



Тестування автоматично виконується в GitHub Actions перед створенням Docker-образу.



\## 7. CI/CD за допомогою GitHub Actions



Автоматизація реалізована у файлі:



```text

.github/workflows/deploy.yml

```



Workflow запускається після внесення змін у гілку `main` або вручну через GitHub Actions.



Процес складається з трьох етапів.



\### Етап 1. Test Node.js



\- Отримання вихідного коду з GitHub.

\- Встановлення Node.js.

\- Встановлення залежностей.

\- Запуск автоматизованих тестів Jest.



\### Етап 2. Build and Push Docker



\- Авторизація в Docker Hub.

\- Створення Docker-образу.

\- Публікація образу з тегами `latest` і SHA коміту.



Репозиторій Docker Hub:



```text

sivanna7/devops-dashboard

```



\### Етап 3. Terraform and EC2 Deployment



\- Налаштування доступу до AWS.

\- Ініціалізація Terraform.

\- Перевірка конфігурації та створення плану.

\- Автоматичне створення або оновлення інфраструктури.

\- Отримання IP-адреси EC2.

\- Тимчасове надання SSH-доступу для GitHub Actions.

\- Копіювання production Docker Compose на сервер.

\- Завантаження Docker-образів.

\- Запуск контейнерів.

\- Перевірка працездатності API.

\- Видалення тимчасового правила SSH-доступу.



\## 8. Інфраструктура Terraform



Terraform використовується для керування ресурсами AWS.



Основні ресурси:



\- EC2 instance `t3.micro`.

\- Ubuntu Server 24.04.

\- Диск EBS `gp3`, 16 ГБ.

\- AWS Security Group.

\- Публічна IPv4-адреса.



Регіон розгортання:



```text

eu-north-1

```



Стан Terraform зберігається в HCP Terraform.



Організація:



```text

sivanna-devops

```



Workspace:



```text

devops-final-project

```



Для перевірки конфігурації використовуються команди:



```bash

terraform init

terraform fmt

terraform validate

terraform plan

```



Створення інфраструктури виконується автоматично через GitHub Actions.



\## 9. Безпека



У проєкті застосовано такі заходи безпеки:



\- Облікові дані AWS зберігаються в GitHub Actions Secrets.

\- Пароль PostgreSQL не додається до Git-репозиторію.

\- SSH-ключ зберігається як GitHub Secret.

\- Порт PostgreSQL не відкривається для зовнішніх підключень.

\- Доступ до HTTP-порту 3000 обмежується AWS Security Group.

\- SSH-доступ GitHub runner надається тимчасово.

\- Файли `.env`, `terraform.tfvars` та приватні ключі виключені з Git.
